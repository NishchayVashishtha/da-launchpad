# 14-case-study-method  (topic: casemethod; 6 practice, text) hub lesson for the 25 written cases
fm: title "How to solve a written business case"; description "A repeatable method for case rounds and take-home business questions, with a map of our 25 cases."; order 14; estimatedMinutes 45; objectives: read a prompt and clarify; structure a case answer; combine numbers with a recommendation; manage time; use the 25 cases for practice; tags: business, case-study, interview, framework
## Concept
- Case types in India: analytics case (data given), product/metrics case, RCA, estimation, take-home. What interviewers score: structure, numbers, insight, communication, recommendation, honesty about limits.
- Method (6 steps): restate + clarify (goal, metric, constraints), hypothesis tree, ask for/ inspect data (cleaning first), analyse (size -> segment -> compare), insight (so what), recommend (action, expected impact, risk, next test).
- Time plan for a 30-minute case; think-aloud tips; when stuck; how to use numbers in a table.
- Answer layout: 1-line answer, 3 findings, recommendation, risks.
- How to use our cases: 25 cases at /business/cases/<id>/ ; order: fintech (10), health (7), consulting (8); attempt with a 20-30 min timer, then open the model solution; self-score using rubric (structure 25, analysis 25, insight 25, recommendation 25).
- Link lists of cases by industry and difficulty (writers: use plain markdown links `/business/cases/<id>/` from cases.md ids).

## Common mistakes
- Jumping to data without clarifying | listing frameworks without numbers | no recommendation | ignoring data quality | long answers without structure | over-claiming from small n.
