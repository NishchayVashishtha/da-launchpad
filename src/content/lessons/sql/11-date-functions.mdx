## Learning objectives

- Know that SQLite has no real date type: dates are ISO text.
- Use `date()`, `datetime()`, `strftime()` and `julianday()`.
- Group by month, week and weekday.
- Add and subtract days, months and years.
- Find the number of days between two dates.
- Translate each idea to MySQL, PostgreSQL and SQL Server.

## Why this matters for a Data Analyst job

<RealWorld>
"Monthly orders", "week-on-week growth", "how many days from order to delivery", "users who signed up in the last 30 days". Almost every business report is a time series. If you cannot bucket by month and compute date gaps, you cannot build a report. Date questions are also among the most common SQL interview tasks.

## Concept

### How SQLite stores dates

SQLite has no separate DATE type. A date is **text** in the ISO 8601 format:

- date: `2024-03-15`
- date and time: `2024-03-15 18:20:00`

This format sorts and compares correctly as plain text, which is why `WHERE order_date >= '2024-01-01'` works. If your dates are not in this format (for example `15-03-2024`), the date functions return NULL. Fix the format first.

### The core functions

| Function | Meaning | Example |
|---|---|---|
| `date(x, modifiers...)` | date part only | `date('2024-03-15 18:20:00')` gives `2024-03-15` |
| `datetime(x, ...)` | date and time | |
| `strftime(fmt, x, ...)` | format or extract | `strftime('%Y-%m', '2024-03-15')` gives `2024-03` |
| `julianday(x)` | days as a number, for subtraction | |
| `'now'` | current time (UTC) | `date('now')` |

### strftime format codes

| Code | Gives | Code | Gives |
|---|---|---|---|
| `%Y` | 4-digit year | `%H` | hour (00-23) |
| `%m` | month (01-12) | `%M` | minute |
| `%d` | day of month | `%w` | weekday, 0 = Sunday |
| `%W` | week of year (Monday-based) | `%j` | day of year |

`strftime` returns **text**. `strftime('%m', d)` is `'03'`, not the number 3. Wrap with `CAST(... AS INTEGER)` if you need a number.

### Modifiers: adding and snapping

Modifiers go after the date:

- `date(d, '+7 days')`, `date(d, '-1 month')`, `date(d, '+1 year')`
- `date(d, 'start of month')`: first day of that month
- `date(d, 'start of year')`
- `date(d, 'weekday 0')`: moves forward to the next Sunday (or stays if already Sunday)

**Week bucketing** (week starting Monday): `date(d, 'weekday 0', '-6 days')`. First jump to the Sunday that ends the week, then step back 6 days to the Monday.

**Month bucketing**: `strftime('%Y-%m', d)` or `date(d, 'start of month')`.

### Date differences

Subtract Julian day numbers:

```sql
julianday(delivery_date) - julianday(order_date)   -- days between
```

The result is a decimal number (1.0 means 1 day). Use `CAST(... AS INTEGER)` for whole days.

### Be careful with 'now'

`date('now')` changes every day, so the same query gives different results over time. For learning with fixed data, prefer fixed dates or compare against `MAX(date)` in the table.

### Other databases

| Task | SQLite | MySQL | PostgreSQL | SQL Server |
|---|---|---|---|---|
| Today | `date('now')` | `CURDATE()` | `CURRENT_DATE` | `CAST(GETDATE() AS DATE)` |
| Year of a date | `strftime('%Y', d)` | `YEAR(d)` | `EXTRACT(YEAR FROM d)` | `YEAR(d)` |
| Month start | `date(d, 'start of month')` | `DATE_FORMAT(d, '%Y-%m-01')` | `DATE_TRUNC('month', d)` | `DATETRUNC(month, d)` (2022+) or `DATEFROMPARTS(YEAR(d), MONTH(d), 1)` |
| Add 7 days | `date(d, '+7 days')` | `DATE_ADD(d, INTERVAL 7 DAY)` | `d + INTERVAL '7 days'` | `DATEADD(day, 7, d)` |
| Days between a and b | `julianday(b) - julianday(a)` | `DATEDIFF(b, a)` | `b - a` (for dates) | `DATEDIFF(day, a, b)` |
| Weekday | `strftime('%w', d)` | `DAYOFWEEK(d)` | `EXTRACT(DOW FROM d)` | `DATEPART(weekday, d)` |
| Format as text | `strftime(fmt, d)` | `DATE_FORMAT(d, fmt)` | `TO_CHAR(d, fmt)` | `FORMAT(d, fmt)` |

<Warning>
Watch the argument order of `DATEDIFF`. MySQL is `DATEDIFF(end, start)`. SQL Server is `DATEDIFF(unit, start, end)`. Mixing them gives the wrong sign.
</Warning>

<Tip>
`BETWEEN` on dates includes both ends. For timestamps, use `>= start_date AND < next_day` so that the full last day is included.
</Tip>

### Example 5: days between two dates

Average days from order to delivery by sales channel.

<SqlPlayground dataset="ecommerce" query={`SELECT sales_channel,

### Example 6: date arithmetic and tenure

How long have HR employees been with the company as of a fixed date, 31 Dec 2024? Using a fixed date keeps the output stable.

<SqlPlayground dataset="hr" query={`SELECT employee_id,

ORDER BY hire_date, employee_id
LIMIT 4;`} title="Tenure and anniversary" />

## Common mistakes

<CommonMistake>
**Using `MONTH(date)` or `DATEDIFF` in SQLite.** They do not exist. Use `strftime` and `julianday`.
</CommonMistake>

<CommonMistake>
**Grouping by month number only** (`%m`). January 2023 and January 2024 merge. Group by `%Y-%m`.
</CommonMistake>

<CommonMistake>
**Using BETWEEN on timestamps** and losing the last day. Use `>= start AND < next_day`.
</CommonMistake>

<CommonMistake>
**Dates in the wrong format.** `15-03-2024` is not ISO, so `strftime` returns NULL and comparisons sort wrongly. Convert to `YYYY-MM-DD` first.
</CommonMistake>

<CommonMistake>
**Relying on `date('now')`** in a practice query. The answer changes every day. Use a fixed date or the maximum date in the data.
</CommonMistake>

## Interview angle

<InterviewAlert>
Date questions test two things: bucketing (month, week) and date arithmetic (days between, last 30 days). Mention which database you are assuming and give the equivalent for others if asked.
</InterviewAlert>

<InterviewQ q="How would you get monthly revenue in MySQL, PostgreSQL, SQL Server and SQLite?">
All use `GROUP BY` on a month bucket. SQLite: `strftime('%Y-%m', d)`. PostgreSQL: `DATE_TRUNC('month', d)`. MySQL: `DATE_FORMAT(d, '%Y-%m-01')` (or `YEAR(d), MONTH(d)`). SQL Server: `DATEFROMPARTS(YEAR(d), MONTH(d), 1)` or `DATETRUNC` in 2022+. The idea is the same: map every date to the first day (or label) of its month.
</InterviewQ>

<InterviewQ q="How do you calculate the number of days between two dates?">
SQLite: `julianday(end) - julianday(start)`. MySQL: `DATEDIFF(end, start)`. PostgreSQL: `end - start` for dates, which gives an integer number of days. SQL Server: `DATEDIFF(day, start, end)`. I would also clarify whether the end date should be counted (add 1 if inclusive).
</InterviewQ>

<InterviewQ q="Why avoid CURRENT_DATE or NOW() in reports that must be reproducible?">
Results change every day, so the same query gives different numbers and is hard to test or compare. For repeatable analysis, I pass a fixed report date as a parameter, or use the latest date in the data. Time zones are another reason: `now` in SQLite is UTC, and Indian business days are in IST (UTC plus 5:30).
</InterviewQ>

## Key takeaways

- SQLite stores dates as ISO text (`YYYY-MM-DD`). Other formats break date functions.
- `strftime` extracts and formats. `date(d, 'start of month')` buckets. `julianday` subtracts.
- Group by `%Y-%m`, not just `%m`.
- Use `>= start AND < next_day` for timestamp ranges.
- Other databases use `DATE_TRUNC`, `EXTRACT`, `DATEDIFF`, `DATEADD`. Know the mapping.
